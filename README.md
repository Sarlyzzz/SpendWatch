# 月度花销（Android 原型）

当前版本：**0.4.2**。本次修复与验证边界见 [CHANGELOG.md](CHANGELOG.md)。

Android 8.0 及以上可安装的本地记账 App。它按北京时间统计自然月消费，并把消费来源（淘宝／抖音等）、付款渠道（支付宝／微信／银行卡直付）和扣款账户分开记录。

## 安装与使用

1. 在项目目录运行 `gradlew.bat assembleDebug`，安装 `app/build/outputs/apk/debug/app-debug.apk`。这是调试签名 APK，适合个人验证，不是商店发布包。
2. 打开「监控」，检查支持的应用是否已安装。需要通知识别时，跳到系统设置授予通知访问。支付宝监控默认开启；其他来源可按需打开。当前手机的微信转账没有可用系统通知，关闭消息去敏也不能让它自动入账。可开启可选的微信屏幕识别，并在微信中打开「微信支付」会话或转账账单详情；未打开的历史交易仍可通过导入账单补齐。若微信消息通知只显示“有一条微信消息”，它本身不会生成交易。
3. 打开「导入」，选择支付宝 CSV、微信 XLSX 或招商银行／中国银行／邮储银行的 PDF／ZIP。加密文件在界面输入密码；密码只用于当次解析，不写入数据库。查看预览后确认导入。
4. 在「待核对」处理银行扣款、转账、退款和疑似重复项。可手动计入、排除、关联退款、合并或拆出交易。「导入」页可撤销整次导入。
5. 在「首页」查看月度净消费和按付款渠道、消费来源的汇总；「设置」可导出 CSV 或清空本机数据。

首页新增「按时间段统计」：选择开始和结束日期（均包含），查看本机已导入、通知或微信屏幕识别的全部交易、已确认消费净额、待核对数量，以及按付款渠道和消费来源的汇总。其他 App 内尚未导出的账单不会自动出现在区间统计中。

首页下拉刷新会重新检查通知栏里仍显示的通知，并刷新本机统计。已从通知栏消失的通知无法回读；可导入账单补齐。「监控」页的「重新检查通知栏」现在会显示检查数量、支付宝通知数量及监听连接情况；每个来源还显示最近一次通知是成功入账、重复，还是因内容不足而跳过。支付宝付款未被记录时，先确认系统通知访问和支付宝开关均已开启，再看该诊断信息。

可选的「微信支付会话与账单识别」需要在「监控」页打开开关并在系统无障碍设置授权。打开微信的「微信支付」会话时，本机离线 OCR 会尝试读取屏幕上可见的卡片：明确的商户支付计入消费，转账凭证进入**待核对**。打开转账账单详情时，若能识别金额、已收钱状态、时间和单号，也会生成待核对记录。微信会话和详情页在当前真机上均未向无障碍文字树暴露字段，因此使用当前屏幕截图；截图与原始 OCR 文字只在内存中处理，不保存。聊天关闭或处于后台时无法读取消息，也不会自动补全未打开的历史账单。会话卡片通常没有交易单号，以日期、时间、金额和类型近似去重；连续两次识别一致才入账。同分钟同额同类型的两笔交易可能被当作一笔，需打开账单详情或导入账单核对。

支付宝的「交易提醒：你有一笔…元的支出」现在可识别为付款；「退款提醒：你收到一笔…元退款」会单独进入待核对。通知里通常缺少原订单号，因此退款需在待核对页核实并关联，避免冲减同金额的其他商品。

## 当前验证范围

- 本地样本测试已覆盖支付宝 CSV 101 行、微信 XLSX 39 行；银行三种版式用提供的 PDF 提取文本验证了招行 17 行、中行 18 行、邮储 28 行。银行 PDF 在 Android 真机上的完整导入仍需安装验证。
- 已在 vivo V2309A（Android 15）真机验证通知访问、监听连接、自检通知回调和「重新检查通知栏」的检查结果显示。安装后系统曾未连接监听，重新允许通知访问后恢复连接。尚未验证真实支付宝付款通知的完整入账流程、系统重启后的监听、不同银行 App 通知文案，以及银行 PDF 在手机上的导入。监控页把通知规则明确标为待真机验证。通知可能漏单，应定期导入账单。
- 银行流水包含转账、充值等非消费扣款。无法可靠确认的记录进入「待核对」，不会直接算进已确认消费。
- 本应用没有服务端、账户登录或自动读取其他 App 内部账本；原始账单文件不会上传。请勿把含真实流水或密码的文件提交到仓库。
